# Parallel-safe change log, generated README/AGENTS index, and automatic push

Every change that touches code now needs one uniquely named file in docs/changes/. A pre-commit hook (.githooks/pre-commit) refuses code commits without a valid one and regenerates the "Recent changes" block in README.md and the change index in AGENTS.md from those files; a post-commit hook runs scripts/sync.py, which fetches, rebases onto the remote branch if someone else pushed, and pushes the current branch. It never force-pushes, and it refuses main/master unless MORAXTERM_ALLOW_MAIN_PUSH=1, matching the existing rule that parallel agents must not push to main. If two contributors regenerate the same block, sync.py resolves that one conflict by regenerating it; any other conflict aborts the rebase and leaves the tree untouched. The previous per-change narrative in AGENTS.md was the single file every contributor edited, so concurrent work guaranteed conflicts. .github/workflows/docs-sync.yml enforces the same rules on pull requests and refreshes the indexes on main. The earlier narrative entries are kept, and six change files back-fill the work from this session.

Verified: python -m unittest test_docs_sync passes 16 tests using real temporary git repos and a bare remote, including two contributors regenerating the same block (both changes survive, no conflict markers), a genuine conflict (aborted, tree untouched, nothing forced), main never pushed automatically, a new branch published on first sync, and CRLF preserved. The pre-commit hook was exercised by hand: a code commit with no change file was refused. The hooks previously skipped themselves because python3 resolved to the Microsoft Store stub on Windows; .githooks/find-python.sh now tries each interpreter until one runs.

Open: the GitHub Action has never run on GitHub (it can only be tested after this is pushed). main is not branch-protected, so the no-direct-push rule is convention plus the hook, not enforced by GitHub. The hooks need python on PATH and one-time sh scripts/install_hooks.sh per clone; --no-verify bypasses them (CI still catches that). Auto-push needs network and valid GitHub credentials.
