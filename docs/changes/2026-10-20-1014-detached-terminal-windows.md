# Open a terminal in its own window (Detach / Return)

Detached terminal windows were the last "not started" item in the UI list. Each terminal pane now has a Detach button that opens the same running terminal in a second OS window, and a Return button that brings it back.

How it works: the process stays owned by the main window's tab, which stays mounted (never unmounted, per the repo rule) and shows a "Return to this tab" placeholder. The native side keeps the last 512 KiB of every terminal's output with a running byte count (`history.rs`); each `terminal-output` event now carries that count. The new window (`?detached=<id>`, `DetachedTerminal.tsx`) subscribes first, then asks for the replay, then drops any live event the replay already covered, so nothing is lost or printed twice. Its typing and right-click paste go to the same terminal, and it sets the PTY size while it is open (the tab does not resize it, and takes over again on return). `detach_terminal` only accepts a running terminal and a plain identifier (letters, digits, `-`, `_`, at most 80 characters), opens at most one window per terminal, and is `async` because a window created from a synchronous command stayed on `about:blank` on Windows (I saw this in the first test run). Closing the window with the X button, Return, or closing the tab gives the terminal back (or ends it, for the tab); closing the main window now ends the application so no separate window outlives it. A restarted terminal keeps its byte count so its new output is never mistaken for old.

Verified: `cargo test` passes (28 passed, 3 ignored) with new unit tests for identifier validation, label round trip, history trimming at line and character boundaries, and the running total after a reset; `cargo fmt --check` clean; `npm run test:unit` 50 pass; `tsc --noEmit` 0 errors; `npm run build` works. `scripts/ui_detached_window_test.py` drives the built exe on a throwaway profile and passed 27/27 on three consecutive runs: a second real OS window named "Local Shell - Moraxterm" opens; it replays output printed before the detach; input typed there reaches the same shell and the output shows in the window and in the tab behind the placeholder, each marker exactly once; `stty size` reports the new window's 36 rows while the tab had 34; a second Detach is not offered; closing with the real window close message (WM_CLOSE, sent through the Win32 API) returns the terminal and the shell still answers; detaching again replays the full history; Return, closing the tab while detached, and closing the main window (the app exits) all clean up. Two test-script mistakes of mine were fixed on the way: the first version closed the window with a debugger command that closes only the page and not the OS window, and one check looked for the wrong badge text. Regression runs on the same build: `ui_smoke_test` all checks true, `ui_session_ops_test` 28/28, `ui_folders_test` 24/24, and `ui_multiexec_test` ALL PASS in 8 of 9 completed runs. The one failure was `excluded_terminal_did_not_receive`, in the first MultiExec run on this build; I did not find the cause and it did not repeat in the eight runs after it, so treat that test as possibly flaky until proven otherwise. A further loop of six runs was cut off by a tool time limit and its results were not recorded. I looked at screenshots of both windows: readable and nothing clipped; the shell prompt shows the Windows user folder, so those screenshots stay out of the repo.

Open: the window shows only the terminal (no split, settings or MultiExec status); text typed in a detached window is not mirrored by MultiExec, because the mirroring runs in the main window. A detached window is not restored after a restart, and its size and position are not remembered. A full-screen program (vim, less) already running when you detach is replayed from its last 512 KiB of output, which may look wrong until it redraws; I did not test this. Only the Windows build was run; Linux was not. Many windows at once were not tested. Two small changes outside this area: `cdp_driver.App` can attach to a page by URL, and the capability file now covers `term-*` windows.

Docs: updated docs/REMAINING_WORK.md (the open-work sentence and a new "Detached terminal windows" known-gap entry) and the AGENTS.md "Known open work" line.
