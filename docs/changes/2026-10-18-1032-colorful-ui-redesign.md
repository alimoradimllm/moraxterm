# Redesign the UI: a coloured icon and graphic for every action, working application themes

Every protocol (8) and every toolbar or navigation action (20) now has its own colour and its own two-tone line graphic, defined in icons.js and drawn as a tinted tile; unit tests fail if two icons share a colour or a shape, or if a protocol and a tool share a colour. The toolbar is grouped (create, layout, tools, settings), the Split and MultiExec buttons show when they are active, and the unicode symbols are gone. The sidebar, tabs, pane bar, home page and session editor use each protocol's colour; the editor's protocol picker shows each protocol's icon, and the home page has a New session tile grid that opens the editor for the chosen protocol. A gradient logo replaces the text mark. react-ui.css is rewritten around colour tokens, replacing the old file that depended on overrides. Application themes (MobaXterm, Midnight, Light, Amber, Neon) previously saved a setting that nothing used; they now switch the interface through data-app-theme, and terminal themes (new theme.js, full 16-colour palettes) also apply to terminals that are already open. The toolbar label Packages is now SFTP, which is what it opens.

Verified: 17 unit tests pass (icons and MultiExec); typecheck, vite build, node --check and git diff --check pass. In the built release exe on an isolated profile, ui_smoke_test.py passes (terminal, typing, Unicode, Ctrl+C, 3000-line output, resize) and ui_multiexec_test.py passes 17 of 17. A screenshot of the real exe with a live terminal showed the active tab, pane bar and state badge styled correctly, and a theme saved in settings applied after reload. Headless Edge screenshots of the built frontend were reviewed for the Neon theme and for a 1000 px window; the home page layout was fixed after the narrow-window shot showed the logo cut off (centering now uses safe center). New scripts/ui_screenshots.py and scripts/ui_theme_shots.py reproduce the browser screenshots.

Open: the Light, Amber and Midnight themes were rendered but not visually reviewed, so icon contrast on the Light theme is unchecked (a brightness filter is applied to icons there as a guess). Light terminal text colours were not checked against real shell output (prompt colours, vim). Only the editor, settings and MultiExec screens were screenshotted; the Macros, Tools, Tunnel and SFTP panels use the new stylesheet but were not looked at. Keyboard focus order and screen-reader labels were not audited. The old src/style.css is still imported and is now mostly unused; removing it needs the legacy main.js path checked first. Dragging tabs, folder management and detached windows are still not implemented.
