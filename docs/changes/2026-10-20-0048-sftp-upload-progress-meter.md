# Show SFTP transfer progress with a bar and a Cancel button, including uploads

The React SFTP pane called `sftp_transfer`, which blocks until the whole file has moved and gives no feedback, and uploads could not report progress at all because the `sftp` client prints no meter when its output is a pipe (I probed it: the batch run prints only `sftp> put ...` lines, while on a terminal it draws `8%  255KB 164.7KB/s`). The queued transfer (`start_sftp_transfer`) already existed and emitted progress for downloads only. Now:

- **Backend:** while a job runs, a poller asks the server for the remote file's size through a second short `sftp ls -ln` connection (about once a second, first after 0.4 s) and emits `sftp-transfer-progress` with the bytes and the local file's size as the total. For a download it reads the remote size once to give the existing local-growth progress a total. It stops by itself when the job ends or is cancelled, skips paths containing wildcard characters (`ls` would expand them), and its size parser accepts only a file or symlink listing line, not a directory, prompt echo or error.
- **Pane:** the SFTP pane now starts transfers with `start_sftp_transfer`, shows a bar and "X of Y (N%)", a Cancel button while running, "Done" or "Stopped", and the failure text in the footer. The numbers go through a small tested module (`transferProgress.js`) that never lets the bar go backwards or past 100%, and shows "size unknown" instead of inventing a percentage.
- **Test hooks:** `MORAXTERM_TEST_SFTP_LIMIT_KBIT` and `MORAXTERM_TEST_SSH_CONFIG` for the SFTP client are no longer compiled out of release builds (the UI tests drive the built exe); both do nothing unless set, the limit accepts digits only.
- **Test server:** `disposable_ssh_ui_server.sh` now has an sftp subsystem and a remote folder, takes `MORAXTERM_TEST_SSH_UI_PORT` with a ready file per port, and refuses to start if the port or ready file is already in use.

Verified: `cargo test` in `tauri-ui/src-tauri` passes (20 passed, 3 ignored) with two new unit tests on real sftp output; `cargo fmt --check` is clean. The ignored integration test `sftp_upload_progress_rises_while_the_file_is_still_being_sent` passed against a throwaway sshd through the Windows `sftp.exe` (samples 255 KB, 510 KB, 765 KB, 1020 KB, 1020 KB, 1275 KB of 1.5 MB, never backwards, all with the total), and the existing round-trip, resume and cancel tests still pass. `npm run test:unit` passes 50 (7 new), `npm run typecheck` has 0 errors, and the Vite build works. `scripts/ui_sftp_progress_test.py` drives the built exe: 15 of 15 checks passed on three consecutive runs (bar present while running with a Cancel button, rose from 8% to 87% and never fell, text "1.7 MB of 2.9 MB (60%)", ended "Done" at 100% with the remote file the full 3,000,000 bytes, a cancelled upload stopped and left an incomplete remote file, and a missing local file showed a failure and created nothing remotely). The server, its temp folder and ready file were removed afterwards. Mistakes on the way: my first server start deleted nothing, but it exposed that two servers share one ready file, so I restored the other session's ready file by hand (its rotation count was lost and reset to 0) and fixed the script so this cannot happen again; my first probe scripts wrote real newlines inside strings and did not run, so I rewrote them.

Open: the number is the remote file's observed size, not bytes the server acknowledged, so it can lead or lag the real transfer; it costs one extra SSH connection per second per transfer, visible in a server's logs. Resuming an upload (`reput`) would show the whole remote size from the start. The React pane has no resume checkbox, queue view, drag and drop or click-to-open remote folders. A password-protected server, a very large file, many transfers at once, the SCP fallback, and a non-OpenSSH server were not tested; only the Windows `sftp.exe` against OpenSSH on Linux was run.

Docs: updated docs/REMAINING_WORK.md (two SFTP lines corrected and a new "SFTP progress" known-gap entry) and the AGENTS.md SFTP line.
