# Bump to 0.1.25 and ship the licence texts inside the Windows installer

The app version moves from 0.1.24 to 0.1.25 (`package.json`, `package-lock.json`, `Cargo.toml`, `Cargo.lock`, `tauri.conf.json`). `tauri.windows.conf.json` now bundles `LICENSES/`, the MIT `LICENSE`, `THIRD_PARTY_NOTICES.md` and `docs/EMBEDDED_UNIX_PACKAGES.md` into the installer under `licenses/`, so the GPL texts and source pointers added in #29 travel with the binaries. The runtime archive keeps its `0.1.24` name on purpose: that is the version of the Unix runtime, which did not change, and the name appears identically in `build.rs`, `main.rs`, `prepare_embedded_runtime.py`, the workflow and the config.

Verified: `npm run tauri -- build` built `Moraxterm_0.1.25_x64_en-US.msi` (135.79 MiB) and `Moraxterm_0.1.25_x64-setup.exe` (135.77 MiB). Listing the NSIS installer with 7-Zip shows `licenses\` with 9 licence texts, the index, the MIT licence, the notices and the package list; four of the texts (GPL-2.0, GPL-3.0, LGPL-3.0, MPL-2.0) are identical to the repository copies once line endings are normalised. The MSI contains 16 files including the same set. The 0.1.24 installer had none of these. I unpacked the 0.1.25 NSIS installer to a temp folder and ran its exe with a throwaway profile on its own port: smoke suite passed with no false checks, MultiExec ALL PASS, folders 24/24, session actions 28/28, Telnet/VNC/SSH 12/12. All 85 distinct MSYS2 source archives still answered HTTP 200.

Open: this is the unpacked installer exe, not an installed copy; install, uninstall, upgrade over 0.1.24 and a clean machine were not tested. The installers are unsigned. The Linux `.deb` and `.rpm` for 0.1.25 were not built. Nothing is tagged or published. CI builds the Windows installer from a repository variable that downloads the runtime archive, and I did not run that workflow.
