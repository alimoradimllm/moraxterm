# Test MultiExec across real SSH tabs against a throwaway sshd, with a test-only ssh config switch

MultiExec had only been checked between local PowerShell shells. This adds `scripts/disposable_ssh_ui_server.sh` (a loopback-only sshd in Debian WSL with a generated key, host key and ssh config in a temporary folder) and `scripts/ui_ssh_multiexec_test.py`, which drives the built exe with three SSH tabs and the Local Shell. To keep `~/.ssh` out of it, SSH terminals now honour `MORAXTERM_TEST_SSH_CONFIG`: when set to a file, `-F <file>` is put first in the ssh arguments; unset or blank it does nothing (`apply_test_ssh_config` in `main.rs`, one unit test). The server script restricts the generated private key to the current user with `icacls` because Windows `ssh.exe` refuses a key other accounts can read.

Verified: 19 checks pass, three runs in a row (run 1 `ALL PASS`, runs 2 and 3 `ALL PASS`): real SSH logins in all three tabs (each answers a command and shows the remote prompt), typing in one SSH tab runs in the other two and in the local shell, an excluded SSH tab does not receive it while the rest do, `✓ sent` shows, after one SSH tab's session ends the other tabs survive and still receive the next command while the ended tab does not, and the banner clears on exit. `cargo test` in `tauri-ui/src-tauri` passes (11 passed, 2 ignored) and `cargo fmt --check` is clean. The server, its temp folder and ready file were gone afterwards; `~/.ssh` was not read or changed (the app read only the temp config). Failures on the way, both mine: the first run failed with "UNPROTECTED PRIVATE KEY FILE" until the key ACL was restricted; then typing into a background tab went nowhere until the test brought the tab to the front.

Open: `sent` still means the PTY accepted the write, not that the command succeeded. Mirroring `exit` ends every tab, which is how MultiExec works, so the test turns it off for that one command. Only the password-less key path was tested; password and SSH-agent logins were not. The remote is a local Debian sshd, not a different OS; there is no per-target stop button yet. The `X11 forwarding ... xauth` warning shown in each tab comes from the app's `-X` flag on a server without xauth, not from this change.
