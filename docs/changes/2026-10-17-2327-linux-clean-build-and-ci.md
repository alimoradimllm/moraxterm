# Make a clean Linux checkout buildable and add a Linux package CI job

A clean checkout of main could not be built on Linux: build.rs panicked because the 137 MB Windows-only MSYS2 runtime archive was missing, and tauri.conf.json listed it as a bundle resource for every platform. The archive is git-ignored and only used on Windows (provision_embedded_runtime returns early elsewhere), so build.rs now requires it only when CARGO_CFG_TARGET_OS is windows, and the archive moved from tauri.conf.json into a new tauri.windows.conf.json, which Tauri merges on Windows only. A new workflow .github/workflows/build-linux.yml builds the .deb and .rpm on ubuntu-24.04 from a clean checkout on pull requests and main, checks the .deb contains no EmbeddedUnix archive, installs it in a clean ubuntu:24.04 container, checks shared libraries resolve, and starts it under xvfb. It uploads artifacts only and never creates a release.

Verified: reproduced the failure first (clean clone of main in Debian WSL: cargo check exit 101, "embedded Unix runtime is missing"). With the three changed files, the same clean clone with no archive passes cargo check (exit 0). Windows is unchanged: with the archive removed, a Windows cargo check still fails with the same message, and a rebuilt NSIS installer (135.73 MiB) still contains the 137,940,124-byte archive, embedded-unix-default-packages.txt and the executable. rust-core and the Tauri crate tests pass on Linux with Rust 1.99.0.

Open: build-linux.yml has not run on GitHub yet; its first run may need fixes (library names, bundle output paths, the docker step). The .rpm is built but never installed or started. Nothing has launched the app with a real display, only under xvfb. Apt's rustc 1.85 cannot build this lockfile (dependencies need 1.88 to 1.90); a plain Debian WSL shell picks it up unless ~/.cargo/bin is first on PATH. The Tauri crate's appindicator and xdo library needs were guessed from the Tauri docs, not checked against Cargo.toml.
