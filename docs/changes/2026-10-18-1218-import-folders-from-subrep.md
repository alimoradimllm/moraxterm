# Put imported MobaXterm folder paths in the session folder field so the tree shows them

The import work in this branch (earlier commits) reads each bookmark section's SubRep path and stores it, with Windows separators changed to /, in the session's group field. The interface builds its folder tree from the folder field (src/folders.js, added with the session folders), so imported sessions would have shown at the top level and the imported hierarchy would have been invisible. The importer now sets folder to the same normalised path as well as group, in both places that build a session, and the existing SubRep test also asserts the folder value.

Verified: cargo test --test bookmarks passes (4 tests, including the folder assertion); the full rust-core suite passes (all suites ok); test_moraxterm_importer passes (5 tests); cargo fmt --check and git diff --check are clean. In the built exe on a throwaway profile, importing a synthetic .mxtsessions file with nested SubRep paths through the real import_sessions command produced the nested folders and sessions in the sidebar tree, and the folders were still there after a page reload (scripts/ui_import_folders_test.py: 4 sessions imported into Labs, Operations/Linux/Production and Operations/Windows, tree and database checked, and folder equals group for every imported session).

Open: only synthetic bookmark data was used; the user's supplied export was not imported. MobaXterm names folders with backslashes, which are converted to /, so a folder name that itself contains a / would be split into two levels. Duplicate names across folders are one database row (the store keys on name), so a later import of a same-named session replaces the earlier one. The two-field group and folder duplication is deliberate for now and should be collapsed to one field later.
