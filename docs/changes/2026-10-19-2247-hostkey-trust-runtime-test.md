# Test the host-key trust flow end to end, and fix three bugs it found

`scripts/ui_hostkey_test.py` drives the built exe against a throwaway sshd (now able to start with an empty known_hosts and to replace its own host key on request) through the whole flow: an unknown host is refused under the strict policy; the editor scans and shows the server's fingerprint; a wrong confirmation is refused and writes nothing; approving stores the key and the session connects; when the server's key is replaced the connection is refused with OpenSSH's "REMOTE HOST IDENTIFICATION HAS CHANGED" warning and the stored key is not overwritten; removing the old key, scanning and approving the new one connects again. A test-only switch, `MORAXTERM_TEST_KNOWN_HOSTS`, points the host-key commands at a throwaway file; unset, they use `~/.ssh/known_hosts` as before.

Bugs found by running it, all fixed:
1. **Scanning a host key often returned nothing on Windows.** The Windows `ssh-keyscan` cannot complete a key exchange with current servers (`choose_kex: unsupported KEX method sntrup761x25519-sha512@openssh.com`), so "Scan fingerprint" said "host-key scan returned no key" for servers whose own `ssh.exe` connects fine. If `ssh-keyscan` returns nothing, the app now asks `ssh` to record the key into a private temporary known_hosts that is deleted straight afterwards; nothing reaches the real file until the user confirms the fingerprint.
2. **"Check known host" and "Remove stored key" used the wrong name for non-default ports.** known_hosts stores `[host]:port`; status checked the bare host, so a host on a non-22 port always showed "not present" even when trusted. Both now use the OpenSSH name (`known_hosts_key`, unit tested).
3. **The host-key commands did not validate the host** the way the SSH launch does; `scan_host_key` now applies `check_target`, so an option-like host is refused.

Verified: the host-key test passes 19 of 19 on three consecutive runs, each with a fresh empty known_hosts and a real key rotation (the server counted three rotations). The scanned fingerprint equals the one `ssh-keygen` computes from the server's own public key, taken separately from the app. `cargo test` in `tauri-ui/src-tauri` passes (14 passed, 2 ignored), including new tests for the port naming, for the ssh fallback cleaning up its temporary folder, and for refusing option-like hosts; `cargo fmt --check` is clean. The SSH MultiExec test still passes against the changed server script. Afterwards the server, its temp folder and ready file were gone, no `moraxterm-hostkey-*` temp folders were left, and the real `~/.ssh/known_hosts` was unchanged (3089 bytes, last modified Oct 14).

Open: the scan fallback was proven against a modern OpenSSH server and an ed25519 key only; RSA/ECDSA-only servers and servers that rely on the old key-exchange list were not tried. `ssh_known_hosts_status` runs `ssh-keygen`, which takes about 6 s per call here when the Git/MSYS `ssh-keygen` is first on PATH and about 1.3 s with the native one (the test pins the native one); the app does not choose, so a user's PATH order changes how slow the buttons feel. The editor has no first-connection prompt of its own: connecting with the "ask" policy is left to OpenSSH inside the terminal, which this test did not exercise. The "Reconnect" button was needed after a refused attempt because clicking the session again only switches to its open tab.
